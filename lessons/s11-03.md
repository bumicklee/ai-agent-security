# 11-3 ★ OWASP 한 장: ASI07 에이전트 간 통신 · ASI08 연쇄 실패
⏱ 약 4분 · 코드 없음

| | ASI07 에이전트 간 통신 (Insecure Inter-Agent Communication) | ASI08 연쇄 실패 (Cascading Failures) |
|---|---|---|
| 쉬운 말 | 에이전트끼리 주고받는 메시지가 **모양도, 보낸 이 확인도, 권한도 없이** 오간다 | 한 곳의 실패·오류가 재시도와 위임을 타고 **팀 전체로 커진다** |
| 방금 본 사고 | 11-2: 주문 담당이 받은 "환불 처리 필요"가 그대로 환불 담당의 일이 됐다 | 11-2: 같은 조회를 끝없이 다시 맡겨 최대 턴·요금까지 갔다 |
| 이 강의에서 할 것 | 메시지 계약(Pydantic), HMAC 서명·nonce·만료, 담당별 권한, 핸드오프 경로 막기(11-4) | 서킷 브레이커, 시간 제한, 재시도 예산(11-5), 사용자별 요금 차단(12-4) |

원문 방어 지침 중 이 섹션에서 하는 것
- ASI07-M1 에이전트별 자격 증명 → 담당별 서명 키(브로커가 보관)(11-4)
- ASI07-M2 메시지 서명 → 담당 사이 메시지에 HMAC 서명(11-4)
- ASI07-M3 재전송 방지 → nonce·만료(11-4)
- ASI07-M9 타입 있는 메시지 계약·스키마 검증 → 결과는 상태·주문 번호 칸만(Pydantic, 11-4)
- ASI08-M1 고장을 전제한 설계 → 담당 하나가 멈춰도 팀은 안전하게 멈춘다(11-5)
- ASI08-M7 피해 범위 제한(할당량·진행 상한·서킷 브레이커) → 담당별 브레이커, 재시도 예산, 시간 제한(11-5)
- ASI02-M5 비용·토큰 상한 → 사용자별 요금 차단(12-4)

SDK가 정한 것 하나: **도구 가드레일은 핸드오프에 돌지 않는다.** 검사를 도구 호출 경로에 걸었다면, 같은 담당으로 가는 핸드오프 경로는 비어 있다.
