# 11-4 지키기: 메시지 계약·서명·담당별 권한, 핸드오프 경로 막기
⏱ 약 15분 · 고칠 파일 2개(새 파일 1개) · 바뀌는 줄 약 40줄(이 섹션에서 가장 깁니다)

## 흐름
```
감독자 ── make(): TaskMessage(sender, receiver, action, task, nonce, expires_at) + 감독자 키로 HMAC 서명
       ── (완성본 crew/runtime/bus.py) ── verify(): 서명·받는 이·만료·nonce·보내는 담당의 권한
       ── 담당 실행 ── contract(): 답을 Result(status, order_ids)로 줄여서 돌려준다
```
키는 브로커가 쥡니다(`crew/runtime/broker.py`의 `agent_key(이름)`). 모델은 보지 못합니다.

## 따라 하기
1. `make check L=11-4` → `기대: 주문 담당의 자유 글이 감독자에게 그대로 가지 않는다` 레드
2. 새 파일 `crew/guards/messages.py`
   ```python
   PERMISSIONS = {"감독자": {"orders", "refunds"}, "리포트 담당": {"reports"}}  # 리포트 담당은 환불을 못 맡긴다


   class Result(BaseModel):  # 담당 → 감독자: 이 칸만 돌아간다
       status: Literal["done", "denied", "error", "pending"]
       order_ids: list[int] = []


   def make(sender, receiver, action, task) -> TaskMessage:
       m = TaskMessage(sender=sender, receiver=receiver, action=action, task=task[:300], nonce=secrets.token_hex(8),
                       expires_at=stamp(now() + timedelta(seconds=TTL_S)))
       m.sig = signature(m.model_dump(exclude={"sig"}), agent_key(sender))
       return m


   def verify(m, receiver) -> str | None:
       # 1) hmac.compare_digest(m.sig, 다시 계산한 서명)  2) 받는 이·만료·nonce  3) PERMISSIONS
   ```
   `contract(text)`: "거부…"→denied, "승인 대기…"→pending, "오류·다시 시도"→error, 그 밖 done. 주문 번호만 뽑습니다.
3. `crew/agents/supervisor.py`의 ✏️ 11-4 자리: `as_tool` 대신 완성본 메시지 경로, 그리고 **핸드오프는 주지 않는다**
   ```python
   return Agent(name="감독자", ..., handoffs=[], tools=[
       agent_tool(orders, name="ask_orders", description="…", action="orders"),
       agent_tool(refunds, name="ask_refunds", description="…", action="refunds"),
   ])
   ```
   - 왜 핸드오프를 빼나: 도구 가드레일·메시지 검사는 **도구 호출 경로**에서만 돕니다. 감독자에게 핸드오프가 있으면 검사 없는 우회 경로가 생깁니다.
4. 확인합니다.
   ```bash
   make check L=11-4
   make redteam S=18
   ```
   18번은 아직 "사고"입니다. 번짐(1001 환불)은 사라졌지만, `{"status": "error"}`를 받은 감독자가 여전히 다시 맡깁니다(11-5).
