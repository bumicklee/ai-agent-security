# 13-2 레드팀 콘솔 replay를 CI 게이트로
⏱ 약 8분 · 코드 없음(완성본 워크플로를 읽고 돌려 본다)

## 무엇이 있나
- `python -m crew redteam --ci`(또는 `make redteam S=--ci`): 20개를 돌려 **사고나 오탐이 하나라도 있으면 1로 끝납니다.** 잠김은 실패가 아닙니다.
- `.github/workflows/redteam.yml`: PR마다 과정 검사(`verify-course`) → 검사할 지점으로 이동 → `make check-all` → 레드팀 게이트. 키 없이 돕니다(`LLM_MODE=fake`).
  새로 받은 저장소에는 진도(`data/progress.json`)가 없으므로 검사할 지점을 `CREW_CI_POINT`로 정합니다. 기본 `"13-5"`는 마지막 수업 완료 지점(정답 전부)에서 전체 시험을 돌립니다. **내 코드 그대로** 게이트에 걸려면 `CREW_CI_POINT: ""`로 바꿉니다(옮기지 않고 내 코드로 레드팀을 돌린다).
  강사가 녹화한 실제 응답(카세트)이 `cassettes/`에 있으면 `LLM_MODE: replay`로 바꿉니다. 수강생 화면과 CI가 같은 응답을 봅니다.
- 네트워크를 쓰지 않습니다. 택배사 MCP는 stdio 하위 프로세스, 리포트 샌드박스는 제한 프로세스 모드입니다.

## 따라 하기
1. 내 랩에서 게이트를 돌립니다.
   ```bash
   make redteam S=--ci ; echo "끝난 값: $?"
   ```
   "레드팀 게이트: 통과", 끝난 값 0.
2. 일부러 깹니다. `crew/tools/orders.py`의 소유권 조건(`AND customer_id = ?`)을 지우고 다시 → 1번 "사고", 끝난 값 1. 되돌립니다.
3. 내 저장소에 올렸다면 PR을 하나 열어 Actions 탭에서 같은 결과를 봅니다.
4. `make check L=13-2`

## 왜 게이트인가
- 모델·SDK·프롬프트·MCP 서버는 내가 모르게 바뀝니다(10-2). 바뀔 때마다 사람이 20개를 눌러 볼 수 없습니다.
- 막힘뿐 아니라 **오탐**도 실패로 칩니다. 정상 고객을 막는 보안은 오래 못 갑니다.

## 기억할 한 줄
보안 시험은 출시 버튼 앞에 둔다. 사고 0, 오탐 0이 아니면 나가지 않는다.
