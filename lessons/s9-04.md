# 9-4 지키기: 모델이 짠 코드를 격리해서 실행하기(관리자 권한 없이, 인터넷 차단, 읽기 전용 DB 복사본, 시간 제한)
⏱ 약 10분 · 고칠 파일 1개 · 바뀌는 줄 약 10줄

## 샌드박스는 두 가지 길로 돈다
| 길 | 언제 | 무엇이 막나 |
|---|---|---|
| 컨테이너 | Docker가 돌고 `python:3.12-slim` 이미지가 이미 있을 때(내려받지 않음) | `--network none`, `--user`(Policy의 `run_as`, nobody = 65534), `--read-only`, `-w /work`(빈 작업 폴더), 메모리·프로세스 한도 |
| 제한 프로세스 모드 | 그 밖(시험은 늘 이쪽) | 하위 프로세스 + 시간 제한 + 빈 임시 폴더 + DB 읽기 전용 사본 + 파이썬 감사 훅(네트워크·다른 프로그램 실행·작업 폴더 밖 쓰기 금지) |

제한 프로세스 모드는 **흉내에 가깝습니다.** 같은 사용자 권한으로 돌기 때문입니다. 실서비스는 컨테이너(또는 gVisor·Firecracker 같은 더 단단한 격리)를 씁니다. `CREW_SANDBOX=docker|process`로 고릅니다. 기본(`auto`)은 컨테이너가 뜨면 컨테이너, 아니면 제한 프로세스 모드이고, 두 길의 결과(오류 글·시간 제한)는 같습니다.

**DB 읽기 전용 사본은 요청한 직원의 매장 것만 담습니다**(완성본). dave(shop-a)가 돌린 리포트 코드에는 shop-b 고객·주문·문의가 없고, 행동 기록·랩 설정(할인 코드)도 없습니다. 사본이라도 다 주면 읽기 권한이 너무 넓습니다.

## 따라 하기
1. `make check L=9-4` → `기대: 리포트 코드는 랩 폴더가 아니라 빈 임시 폴더에서 돈다` 레드
2. `crew/tools/reports.py`의 ✏️ 9-4 자리
   ```python
   POLICY = sandbox.Policy(
       timeout_s=5,            # 시간 제한
       network=False,          # 네트워크 차단
       db="readonly-copy",     # DB 읽기 전용 사본
       workdir="temp",         # 빈 임시 폴더(랩 폴더가 아니다)
       run_as="nobody",        # 관리자 권한 없이 실행(컨테이너 모드)
   )
   ...
   r = sandbox.run(code, POLICY)
   ```
3. 확인합니다.
   ```bash
   make check L=9-4
   make redteam S=15
   ```
   15번: "막힘 · ③ 샌드박스". 코드는 똑같이 `rmtree`를 불렀지만 빈 임시 폴더라 지울 것이 없습니다. `data/reports_tmp`는 그대로입니다.
   16번은 아직 "사고"입니다. 전송은 막혔지만 shop-a 고객 연락처 21개가 답에 나옵니다(9-5). 9-1에서는 두 매장 40개였습니다. 사본이 내 매장 것만이라 줄었습니다.
