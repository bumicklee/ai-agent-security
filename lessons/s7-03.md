# 7-3 지키기: 위임 토큰(요청한 사람 권한만큼·짧게·좁게)과 비밀값 브로커
⏱ 약 12분 · 고칠 파일 2개(새 파일 1개) · 바뀌는 줄 약 25줄

## 흐름
```
dave가 "대신 처리" → (완성본) delegation.issue(dave, 목적) → 토큰 번호를 ctx.context.delegation에
  → 모델은 토큰을 모른다(인자·지시문 어디에도 없음)
  → 도구가 broker.redeem(토큰, "orders:write") → Grant(store_id="shop-a", …) 또는 None
  → SQL에 AND store_id = grant.store_id
```

## 따라 하기
1. `make check L=7-3` → `기대: dave의 위임 토큰은 shop-a 것이라 shop-b 주문을 못 고친다` 레드
2. 새 파일 `crew/guards/delegation.py`. 완성본 게이트웨이가 대신 처리 때마다 `issue()`를 부릅니다.
   ```python
   TTL_MINUTES = 10                # 짧게
   SCOPES = ("orders:write",)      # 좁게


   def issue(staff, purpose: str) -> str:
       token = secrets.token_hex(8)
       expires = stamp(now() + timedelta(minutes=TTL_MINUTES))  # 랩 시계(crew/runtime/clock.py)
       with session() as db:
           db.execute("INSERT INTO delegations(token_id, staff_id, store_id, scopes, purpose, expires_at) "
                      "VALUES (?, ?, ?, ?, ?, ?)",
                      (token, staff.id, staff.store_id, ",".join(SCOPES), purpose[:100], expires))
       return token
   ```
   - 시각은 랩 시계(`from crew.runtime.clock import now, stamp`)로 적습니다. 브로커도 같은 시계로 만료를 봅니다.
3. `crew/tools/staff.py`의 ✏️ 7-3 자리. 서비스 계정을 버리고 토큰으로, 그 매장 주문만.
   ```python
   grant = redeem(ctx.context.delegation, "orders:write")  # 토큰은 ctx에만 있다. 모델은 모른다
   if grant is None:
       return "거부: 유효한 위임 토큰이 없습니다(없음·만료·폐기·범위 밖)."
   new_address = new_address.strip()[:100]
   with session() as db:
       cur = db.execute("UPDATE orders SET address = ? WHERE id = ? AND status = 'paid' AND store_id = ?",
                        (new_address, order_id, grant.store_id))
   ```
   - `redeem()`은 완성본 브로커입니다. 없음·만료·폐기(`revoked`)·범위 밖이면 `None`입니다. 12-4의 "토큰 일괄 폐기"가 이 칸을 씁니다.
4. 확인합니다.
