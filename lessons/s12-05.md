# 12-5 사고 대응 한 장과 레드팀 콘솔 20개 모두 그린
⏱ 약 8분 · 코드 없음(시험 하나)

## 사고가 났을 때 순서 (한 장)
| 순서 | 할 일 | 랩에서 |
|---|---|---|
| 1. 멈춘다 | 번지는 것부터 끊는다. 전체를 끌지, 담당 하나만 끌지 고른다 | `/ops` 킬 스위치 · 담당 멈춤 · MCP 차단 |
| 2. 권한을 걷는다 | 대신 처리 토큰·키를 폐기한다. 새 키는 사고가 정리된 뒤에 | **위임 토큰 일괄 폐기**, OpenAI 키 폐기(1-4) |
| 3. 기록을 지킨다 | 고치기 전에 기록부터 떠 둔다. 체인이 온전한지 본다 | `/ops` 행동 기록 체인 · `sqlite3 data/cs_crew.db .dump audit_log > incident.sql` |
| 4. 범위를 잰다 | 누가, 무엇을, 언제부터. run_id로 묶어 본다 | 타임라인의 `[run_id]` · `SELECT * FROM audit_log WHERE run_id = …` |
| 5. 되돌린다 | 돈·데이터·메모를 원래대로. 사람이 승인한다 | 환불 취소(직원), 메모 되돌리기(8-4), `make seed`(랩만) |
| 6. 막는다 | 같은 사고가 다시 안 나게 규칙·시험을 더한다 | 레드팀 시나리오 + `tests/` + CI 게이트(13-2) |
| 7. 알린다 | 고객·직원·운영에 무엇이 있었고 무엇을 했는지 | (랩 밖) |

## 따라 하기
1. 레드팀 20개를 모두 돌립니다.
   ```bash
   make redteam
   ```
   20줄 모두 그린 "막힘", 오탐 없음이어야 합니다. 어느 층이 막았는지(② 가드레일 / ③ 내 코드 / 킬 스위치 / 요금 차단)를 읽어 보세요. ① 모델 자체에 기댄 줄은 없습니다.
2. 시험으로도 확인합니다.
   ```bash
   make check L=12-5
   ```
3. 하나를 일부러 깨 봅니다. `crew/guards/killswitch.py`의 `respond()`를 `pass`로 바꾸고 `make redteam S=19` → "사고". 되돌립니다.

## 기억할 한 줄
사고 대응은 멈추고 · 걷고 · 지키고 · 재고 · 되돌리고 · 막고 · 알린다. 랩에서 한 번 해 본 순서는 실전에서도 손이 기억한다.
