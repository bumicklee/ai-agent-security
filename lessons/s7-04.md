# 7-4 미션: 직원 dave와 carol의 권한 차이를 팀 전체가 지키게 하기
⏱ 약 10분 · 스스로 해 보는 수업 · 고칠 파일 1개

## 지금 상태
| 일 | dave(shop-a) | carol(shop-b) | 누가 지키나 |
|---|---|---|---|
| 대신 처리: shop-a 주문 | 된다 | 막힌다 | 위임 토큰(7-3) ✔ |
| 대신 처리: shop-b 주문 | 막힌다 | 된다 | 위임 토큰(7-3) ✔ |
| 내부 문서 검색 | 에이샵 위키만 | 비샵 위키만 | 테넌트 필터(5-6) ✔ |
| **환불 승인: shop-a 고객 요청** | 된다 | **된다** ← 구멍 | ? |

carol로 `/staff`에 들어가면 승인 대기열에는 자기 매장(shop-b) 카드만 보입니다. 완성본 화면이 매장으로 거르기 때문입니다.
그런데 **화면에서 숨긴 것은 권한 검사가 아닙니다.** 승인 번호만 알면 carol도 alice(shop-a)의 환불을 승인할 수 있습니다.
```bash
curl -s -X POST http://127.0.0.1:8000/api/approvals/1 -H 'Content-Type: application/json' \
     -b crew_user=carol -d '{"approve": true}'
```
시험 `test_carol은_shop_a_환불을_승인하지_못한다`도 같은 길(`decide()`)로 누릅니다.

## 미션
`crew/guards/approval.py`의 ✏️ 7-4 자리에 `can_decide(staff, card)`를 만드세요. 완성본(`crew/runtime/approvals.py`)이 승인·거절 전에 이 함수를 부릅니다.
1. 직원은 **자기 매장** 요청만 승인·거절할 수 있다(`card["store_id"]`)
2. 막을 때는 `"거부: …"`로 시작하는 이유를 돌려준다. 통과면 `None`
3. 같은 매장 직원(dave, erin)의 승인은 그대로 된다(6-5의 두 사람 승인도)

## 확인
```bash
make check L=7-4
```
alice로 환불을 요청해 승인 대기를 만든 뒤, 위 curl을 보내 보세요. 답에 "거부: carol(shop-b)는 shop-a 매장 요청을 승인할 수 없습니다."가 나와야 합니다.

## 힌트 (먼저 스스로 해 보고 펼치기)
