# 9-3 ★ OWASP 한 장: ASI05 예상 밖 코드 실행
⏱ 약 4분 · 코드 없음

| | ASI05 예상 밖 코드 실행 (Unexpected Code Execution, RCE) |
|---|---|
| 쉬운 말 | 에이전트가 만들거나 받은 코드·명령이 **의도하지 않은 곳에서, 의도하지 않은 권한으로** 실행된다 |
| 방금 본 사고 | 9-2: 문의 본문의 숨은 지시가 리포트 코드가 되어 랩 폴더를 지웠다. 16번: 고객 전체 목록을 뽑아 밖으로 보내려 했다 |
| 도구 오용(ASI02)과 차이 | ASI02는 "있는 도구를 잘못 쓴다". ASI05는 도구가 **아무 코드나 돌리는 문**이라, 할 수 있는 일의 경계가 사라진다 |
| 이 강의에서 할 것 | 샌드박스(빈 임시 폴더·DB 읽기 전용 사본·네트워크 차단·시간 제한·관리자 권한 없음, 9-4), 실행 전 검사와 결과 크기 제한(9-5) |

원문 방어 지침 중 이 섹션에서 하는 것
- ASI05-M1 출력 처리(모델이 만든 코드·결과를 믿지 않기) → 실행 전 검사, 결과 크기 제한·개인정보 가리기(9-5)
- ASI05-M2 운영 시스템에 직접 닿지 않게 → 내 매장 줄만 담은 DB 읽기 전용 사본(9-4)
- ASI05-M3 운영 코드에서 `eval`·`exec` 금지 → 랩 폴더에서 그대로 돌리던 실행을 샌드박스 실행으로 교체(9-4)
- ASI05-M4 root 금지·격리·엄격한 제한 → 관리자 권한 없음, `--network none`/감사 훅, 작업 폴더 밖 쓰기 금지, 시간 제한(9-4)
- ASI05-M5 실행마다 새 격리 환경 → 실행마다 새 컨테이너(또는 새 임시 폴더·하위 프로세스)(9-4)
- ASI05-M6 허용 목록 + 사람 승인 → import 허용 목록, 목록 밖 모듈은 직원 승인(9-5)
- ASI05-M7 실행 전 정적 검사 → AST 검사로 금지 모듈·호출 막기(9-5)

## 기억할 한 줄
코드를 실행하게 했다면, 실행되는 곳이 경계다. 경계는 프롬프트가 아니라 프로세스가 지킨다.
