## 따라 하기
1. `make check L=9-5` → `기대: 실행 전 검사 check()를 만든다` 레드
2. 새 파일 `crew/guards/code_check.py`. 리포트 코드는 `q()`로 읽고 `show()`로 내기만 하면 됩니다. 그 밖은 막습니다.
   ```python
   BANNED_MODULES = {"os", "sys", "subprocess", "socket", "shutil", "urllib", "http", "requests", "pathlib", "ctypes",
                     "importlib", "multiprocessing", "sqlite3", "pickle"}
   BANNED_CALLS = {"open", "eval", "exec", "compile", "__import__", "getattr", "setattr", "globals", "vars", "input"}


   def check(code: str) -> str | None:
       tree = ast.parse(code)            # 문법 오류면 "거부: …"
       for node in ast.walk(tree):
           # import / from … import 의 맨 앞 이름이 BANNED_MODULES면 거부
           # 이름으로 부르는 함수가 BANNED_CALLS면 거부
           # 밑줄 두 개 속성(__class__ 등)이면 거부
       return None
   ```
   `limit(text)`: 25줄·2000자를 넘으면 `"거부: 결과가 너무 큽니다…"`
3. **import 허용 목록 + 승인.** 금지 목록만으로는 처음 보는 모듈이 그냥 돕니다. 계산·정리용만 바로 돌리고, 그 밖은 직원이 승인한 뒤에 돌립니다.
   ```python
   ALLOWED_IMPORTS = {"math", "statistics", "collections", "json", "datetime", "csv"}


   async def needs_review(ctx, params: dict, call_id: str) -> bool:   # run_python의 needs_approval
       extra = imports(params.get("code", "")) - ALLOWED_IMPORTS        # imports(): import 이름들(맨 앞)
       return bool(extra) and not extra & BANNED_MODULES                # 금지 모듈은 승인 없이 check()가 거부
   ```
4. `crew/tools/reports.py`의 ✏️ 9-5 자리: `@function_tool(needs_approval=needs_review)`, 돌리기 전 `check()`, 돌린 뒤 `limit()`. 승인 대기는 6-1의 승인 대기열(`/staff`)에 쌓입니다.
5. 확인합니다.
   ```bash

   make redteam S=16
   ```
