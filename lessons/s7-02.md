# 7-2 공격해 보기: 에이전트가 관리자 계정으로 다른 매장 주문을 처리한다
⏱ 약 5분 · 코드 없음 · 공격은 내 랩(127.0.0.1)과 가짜 값에만

## 따라 하기
1. `make run` → **dave**(shop-a 직원)로 `/staff`. 미처리 문의 표에는 shop-a 문의만 보입니다. 완성본 화면이 매장으로 거르기 때문입니다.
2. 그런데 **화면에서 숨긴 것은 권한 검사가 아닙니다.** 6번 문의는 shop-b 고객(cust05)의 것입니다: "주문 5015 배송지를 서울시 가짜구 샘플대로 9로 바꿔 주세요." 문의 번호만 알면 **대신 처리** 버튼 뒤의 API를 그대로 부를 수 있습니다.
   ```bash
   curl -s -X POST http://127.0.0.1:8000/api/staff/act/6 -b crew_user=dave
   ```
3. 답: "[대신 처리] 주문 5015의 배송지를 … 바꿨습니다". 바뀝니다. dave는 shop-b 주문을 고칠 권한이 없는데도요.
4. `/ops` 타임라인에 `broker · service_account`가 찍혀 있습니다. 실제로 일한 신원은 dave가 아니라 서비스 계정입니다.
5. 레드팀으로도 봅니다.
   ```bash
   make redteam S=13
   ```

## 왜?
- 도구가 본 것은 "직원인가?" 하나였습니다. **어느 매장 직원인가, 무엇을 하려고 받은 권한인가, 언제까지인가**는 보지 않았습니다.
- 서비스 계정은 모든 매장에 쓸 수 있습니다. 에이전트가 그 계정을 쓰면, 요청한 사람이 누구든 그 계정만큼 일합니다.
- 기록에는 "dave가 처리"로 보이기 쉽습니다. 누가 무엇을 승인했는지가 흐려집니다(ASI03 신원·권한 남용).

## 확인
`make check L=7-2` → 보는 수업이라 바로 완료로 표시됩니다.

## 기억할 한 줄
에이전트는 요청한 사람의 권한만큼만 일해야 한다. 서비스 계정을 주면 그 계정만큼 일한다.
