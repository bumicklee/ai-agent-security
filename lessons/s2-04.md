# 2-4 지키기: 로그인 사용자 정보는 도구가 직접 받는다, 소유권은 SQL에서, `run_sql` 대신 좁은 도구
⏱ 약 8분 · 고칠 파일 1개 · 바뀌는 줄 4줄

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make check L=2-4
   ```
   `기대: bob에게 alice 주문 내용이 보이지 않는다`가 레드로 나옵니다.
2. **고칩니다.** `crew/tools/orders.py`에서 ✏️ 2-4 표시를 찾아 아래처럼 바꿉니다.
   ```python
   user = ctx.context.user  # 누가 묻는가: 로그인 정보에서 온다. 모델이 정할 수 없다
   with session() as db:
       row = db.execute("SELECT * FROM orders WHERE id = ? AND customer_id = ?",
                        (order_id, user.id)).fetchone()
   if row is None:
       return "거부: 내 주문이 아니거나 없는 주문입니다."
   ```
   - `user_id`를 도구 인자로 받지 않습니다. 인자는 모델이 채우므로 거짓말할 수 있습니다.
   - 거부 글은 `거부:`로 시작합니다. `/ops` 점수판이 이 글자로 "③ 내 코드가 막았다"를 압니다.
   - 남의 주문인지 없는 주문인지 구분해 알려 주지 않습니다.
3. **확인합니다.**
   ```bash
   make check L=2-4
   ```
4. **눈으로 봅니다.** `make run` → `/ops` → 레드팀 1번 → 그린 "막힘 · ③ 내 코드". 같은 줄에 "오탐" 표시가 없으면 bob의 자기 주문(2001)은 그대로 보인다는 뜻입니다.

## 막히면
- `make solution L=2-4` → 내 코드와 정답의 차이가 색으로 나옵니다.
- `make apply-solution L=2-4` → 정답으로 덮어씁니다(내 파일은 `data/backup/`에 남습니다).

## 기억할 한 줄 (레시피 1)
모델이 정하게 두지 않을 것: 누가 묻는가. 도구가 로그인 정보로, SQL 조건으로 막는다.
