# 3-5 openai-guardrails와 출력 가드레일: fail-closed로 켜기, 가드레일이 못 막는 것
⏱ 약 12분 · 고칠 파일 3개(새 파일 1개) · 바뀌는 줄 약 25줄

## 먼저 사고부터
판별기가 고장 난 상황을 만듭니다. 레드팀 5번은 실험용 고장 스위치(`guard_fault`)를 켜고 5번 메일을 보냅니다.
```bash
make check L=3-5      # 기대: 판별기가 고장 나도 숨은 지시대로 쿠폰이 나가지 않는다 → 레드
make redteam S=5      # 사고: 판별기가 시간 초과 → 3-4의 except가 통과시킴 → 쿠폰 발급
```
가드레일은 고장 났는데 화면에는 아무 경고도 없습니다. 이것이 fail-open입니다.

## 따라 하기
1. **고장 나면 막습니다(fail-closed).** `crew/guards/injection.py`의 ✏️ 3-5 자리
   ```python
   except Exception as e:  # 판별기가 고장 나면 막는다(fail-closed). 통과시키면 고장 난 줄 아무도 모른다
       return GuardrailFunctionOutput(output_info=f"판별기 오류, 막음: {e}", tripwire_triggered=True)
   ```
2. **출력 가드레일을 만듭니다.** 새 파일 `crew/guards/output.py`. 고객에게 나가는 답에 내부 코드나 **다른 사람의** 연락처가 있으면 막습니다.
   ```python
   INTERNAL = re.compile(r"FAKE-(?:STAFF|INTERNAL|SVC)[A-Z0-9-]*")
   CONTACT = re.compile(r"[\w.-]+@[\w.-]+\.example|010-\d{4}-\d{4}")


   @output_guardrail
   async def leak_guard(ctx, agent, output) -> GuardrailFunctionOutput:
       user, text = ctx.context.user, str(output)
       found = [] if user.is_staff else [m.group(0) for m in INTERNAL.finditer(text)]
       with session() as db:  # 다른 사람의 연락처인가? (내 것이거나 DB에 없는 번호는 통과)
           for c in CONTACT.findall(text):
               owner = db.execute("SELECT id FROM users WHERE email = ? OR phone = ?", (c, c)).fetchone()
               if owner and owner["id"] != user.id:
                   found.append(c)
       return GuardrailFunctionOutput(output_info={"found": found}, tripwire_triggered=bool(found))
   ```
3. **상담원에게 붙입니다.** `crew/agents/counselor.py`
   ```python
   output_guardrails=[leak_guard],
   ```
4. **확인합니다.**
   ```bash
   make check L=3-5
   make redteam S=5
   ```
   5번은 "막힘 · ② 가드레일", 오탐 없음(판별기가 멀쩡할 때 2번 메일은 통과).

## openai-guardrails를 설치하면
- `pip install -r requirements-extra.txt`로 설치할 수 있습니다(선택). 없어도 랩은 우리 래퍼(`injection_guard`)로 같은 수업을 합니다.
- 이 라이브러리도 검사 중 오류가 나면 **통과가 기본**입니다. 설정에서 `raise_guardrail_errors=True`를 켜야 fail-closed가 됩니다. 오늘 고친 것과 같은 함정입니다.

## 가드레일이 못 막는 것
- 판별기는 교과서 문장을 잘 잡지만, 모델이 실수로 남의 주문을 여는 것(2-2)은 못 막습니다. 그건 도구의 소유권 검사(③ 내 코드) 몫입니다.
- fail-closed는 판별기가 죽으면 상담도 멈춥니다. 그래서 판별기 오류는 `/ops` 타임라인에 `blocked … guardrail`로 꼭 보이게 남깁니다.
